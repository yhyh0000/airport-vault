# 机场钥仓产品设计

## 定位

机场钥仓不是把机场网页塞进代理客户端，也不是把三个开源项目的页面拼在一起。
它是一座本地优先的移动端“机场管理仓”：用户可以集中管理多个机场账户、订阅来源、签到状态、流量与节点运行状态；机场网页只负责完成站点特有的登录与验证，应用负责统一管理和呈现结果。

## 三个参考项目的边界

| 参考项目 | 吸收的能力 | 不直接照搬的部分 |
| --- | --- | --- |
| Yucon | 多账号看板、状态筛选、账户卡片、批量同步与签到 | AI 站点、密钥管理和它的品牌视觉 |
| SlClash | Mihomo 内核承载、订阅/配置/代理链路、Android 生命周期和高信息密度控制 | 原有页面层级不作为机场业务的最终信息架构 |
| linux-sb-mobile | 官方网页结构解析、Cookie 会话、本地状态、移动端 WebView 业务适配和结构自查 | 社区内容、论坛业务与 React Native 页面实现 |

网页适配层必须保持独立：机场页面变化时只更新 adapter，不把站点选择器、HTML 正则和登录态处理散落到 UI 中。

## 机场钥仓自己的设计语言

### 视觉关键词

“仓库感、状态感、轻量运维感”。界面要让用户一眼看到有哪些机场、哪个需要处理、订阅是否新鲜、代理是否正在运行。

### 颜色令牌

- Vault Indigo `#5B61FF`：主操作、iKun、链接和选中状态。
- Signal Teal `#2CC7C9`：Pokemon、同步成功、网络状态。
- Ink Navy `#17213F`：深色主题的背景与高层级文本。
- Paper `#F6F7FB`：浅色主题页面底色。
- 状态色只表达状态：成功、提醒、失败、过期，不用于装饰性渐变。

机场颜色只作为身份标签，不改变整套页面布局；这样用户切换机场时仍然知道按钮在哪里。

### 布局规则

- 首页首屏先呈现“总状态”，再呈现单个机场卡片。
- 账号、订阅和节点是三个独立对象：账号登录成功不等于订阅已经导入，订阅导入成功也不等于代理已经启动。
- 高频动作保持在卡片内：绑定、刷新、签到、导入、复制；危险动作放进详情页。
- 所有手动导入入口必须可见，不能只在自动解析成功后显示。
- WebView 只占业务内容区域，外层始终使用机场钥仓的标题、状态栏、错误提示和完成操作。

## 信息架构

### 1. 总览

展示全局代理运行状态、今日流量、已绑定机场数量、待处理提醒和最近同步记录。首屏提供“粘贴订阅链接”“添加机场”“启动/停止”三个入口。

### 2. 机场

每个机场是一张状态卡，包含：账户标识、流量/到期、签到状态、订阅状态、最近同步时间和待处理错误。点击进入机场详情，完成绑定、刷新、签到、订阅复制和手动导入。

### 3. 订阅

这是所有 Profile 的仓库，不依赖机场账户是否绑定。支持完整 URL、剪贴板、二维码、文件和机场自动发现；每条订阅显示来源、请求头状态、更新状态、节点数量、流量头和到期时间。

### 4. 节点

沿用 SlClash 的 Mihomo 运行语义，集中处理策略组、节点、延迟测试、代理模式和启动状态。机场业务不改写节点配置，只提供来源和状态。

### 5. 工具与设置

包含备份恢复、网页适配诊断、网络路由、资源更新、主题、隐私和关于。网页解析失败时，诊断页要显示入口、最终 URL、HTTP 状态、Cookie/Token 是否存在和解析阶段，而不是只显示“网络错误”。

## 核心业务流程

```text
添加机场账户 ──> 官方网页登录 ──> 保存本地会话 ──> 同步账户快照
                                      │
                                      ├──> 自动发现订阅 ──> 订阅仓库 ──> Mihomo 节点
                                      └──> 手动粘贴订阅 ──> 订阅仓库 ──> Mihomo 节点
```

自动发现失败不能阻断手动导入；登录失效不能删除已有订阅；订阅更新失败不能清空上一次可用节点。

## 业务闭环修正版

### 先解决当前版本的断点

当前版本存在两个直接问题：

1. 登录成功后只保存 `AirportSession` 并刷新账户快照，没有继续执行“发现订阅并创建 Profile”。
2. “复制订阅地址”依赖 `snapshot.subscriptionUrl` 非空；解析失败时整个复制入口消失，用户既看不到订阅来源，也没有下一步指引。

因此，登录成功必须被定义为一个任务流程，而不是一个页面返回事件：

```text
登录完成
  → 保存安全会话
  → 同步账户资料
  → 探测订阅来源
  → 自动导入 Clash/Mihomo Profile
  → 绑定机场与 Profile
  → 展示订阅地址、复制、更新、打开来源页
```

无论自动探测结果如何，机场详情都必须保留一个固定的“订阅中心”区域：

- 已发现：显示脱敏后的订阅地址、复制、重新导入、更新订阅。
- 已自动导入：显示“已连接到节点列表”和对应 Profile 名称。
- 未发现：显示“打开机场订阅中心”“重新同步”“手动粘贴订阅”。不能只显示一个无意义的错误。
- 已失效：保留上一次可用 Profile，显示“登录态失效，仅影响自动更新”，不能删除节点。

### 统一业务对象

机场账户、订阅来源和节点运行态必须分开建模：

| 对象 | 负责内容 | 关键字段 |
| --- | --- | --- |
| AirportAccount | 登录和机场业务 | 机场类型、入口、Cookie/Token、账户名、流量、到期、签到 |
| SubscriptionSource | 订阅来源和导入 | URL、来源页面、格式、请求头、发现状态、Profile ID、最后更新 |
| RuntimeProfile | Mihomo 运行配置 | Profile ID、当前策略组、节点数、更新时间、运行状态 |

一个机场可以拥有多个订阅来源，但默认只自动维护一个主订阅；手动导入的订阅不能被自动同步任务覆盖。

### 自动发现策略

iKun 适配器登录后按以下顺序访问并解析：

1. `/user`：读取首页上的订阅按钮、`data-url`、复制文本和订阅令牌。
2. `/user/profile`：读取账户信息及主题中放置的订阅字段。
3. `/user/subscribe`：读取专门的订阅中心页面。
4. `/user/subscribe_log`：只读取订阅使用记录，绝不把它当成订阅 URL。

从 SSPanel 风格页面中优先生成 Clash/Mihomo 格式；若页面只给出基础令牌，则生成对应的 `/sub/{token}/clash` 候选，并以实际 HTTP 响应验证后再保存。Pokemon 优先调用其订阅 API，再回退到页面解析。

发现多个地址时，选择顺序为：Clash/Mihomo > SingBox > 通用订阅；每个候选都要验证返回内容和 `Subscription-Userinfo`，不能仅凭 URL 字符串判断成功。

## 页面与导航设计

底部固定五个入口，机场管理和代理运行不再混在一个临时卡片里：

### 1. 总览｜全局状态

首屏顺序：

1. 顶部“机场钥仓”品牌和当前 Mihomo 运行状态。
2. 总流量、今日使用、已绑定机场、待处理事项四个轻量指标。
3. iKun / Pokemon 的机场摘要卡：账户状态、订阅状态、签到状态、到期时间。
4. 快捷动作：启动代理、同步全部、签到全部、粘贴订阅。
5. 最近活动：登录、签到、订阅更新及失败原因。

总览只做决策和快捷操作，不承载完整账户详情。

### 2. 机场｜账户仓

使用双卡或列表布局，每张卡固定包含：

- 顶部：机场图标、名称、入口延迟和绑定状态。
- 中部：账户名、流量进度、到期日期、今日签到。
- 订阅条：未配置 / 发现中 / 已连接 / 更新失败。
- 底部：账户详情、同步、签到、订阅中心四个动作。

点击机场进入详情页，而不是继续使用不可扩展的底部弹窗。

机场详情页分为“账户概况、订阅中心、签到记录、诊断”四段。订阅中心是主区块，必须直接提供复制地址和导入状态。

### 3. 订阅｜来源仓

每条订阅使用一张卡片：

- 来源标签：iKun / Pokemon / 手动导入。
- Profile 名称和当前状态。
- 地址默认脱敏显示，点击后可展开；始终提供复制按钮。
- 更新于、下次自动更新、流量头、到期时间、节点数量。
- 操作：立即更新、设为当前、复制地址、编辑请求头、删除。

页面顶部的“添加订阅”使用四个并列入口：粘贴 URL、扫描二维码、选择文件、从已绑定机场发现。不能把 URL 导入藏在配置页的二级菜单里。

### 4. 节点｜运行台

保留 SlClash 的 Mihomo 运行能力，但调整成机场钥仓语义：

- 顶部显示当前 Profile、核心运行状态和启动/停止。
- 中部显示策略组、当前节点、延迟和测速。
- 支持按机场来源筛选节点。
- 订阅更新完成后提示“新增、移除、变化”摘要。

这里不负责账号登录，也不显示机场网页。

### 5. 工具｜维护中心

包含备份恢复、网络诊断、机场入口测速、网页结构诊断、日志脱敏导出、主题和隐私设置。所有适配器错误都要显示阶段：入口探测、网页登录、会话读取、账户同步、订阅发现、订阅下载、Profile 校验。

## 登录后的交互结果

登录页面点击“完成绑定”后，页面不直接无提示地返回首页，而是返回一个绑定任务结果：

```text
账户已绑定
账户资料已同步
订阅地址已发现
订阅已导入到「iKun 主订阅」
```

随后进入机场详情的“订阅中心”，提供：

- 一键复制订阅地址；
- 一键打开订阅来源页；
- 一键更新订阅；
- 查看当前 Profile；
- 重新发现订阅。

如果订阅发现失败，仍然进入同一个订阅中心，但状态变为“需要补充订阅来源”，并把“打开机场订阅中心”和“粘贴订阅链接”放在主按钮位置。这样用户不会陷入“已登录但不知道下一步做什么”的死路。

## 页面布局与配色

- 页面底色使用 Paper `#F6F7FB`，卡片使用白色或主题卡色，减少大面积纯色块。
- 主操作使用 Vault Indigo `#5B61FF`；iKun 卡片只使用 Indigo 的浅色背景和状态线。
- Pokemon 使用 Signal Teal `#2CC7C9`；只表达来源身份和同步成功，不把所有按钮染成青色。
- 运行正常使用绿色，提醒使用琥珀色，错误使用红色；状态色不能替代机场身份色。
- 页面采用 20dp 外边距、16–20dp 卡片圆角、8/12/16dp 间距层级；按钮文案统一使用动作动词：绑定、同步、签到、发现、导入、复制、更新。
- 详情页采用“状态摘要 → 主任务卡 → 次要信息 → 危险操作”的垂直顺序，避免用户在长网页或设置菜单中寻找关键动作。

## 分阶段实施

### Phase 1：核心链路

- 恢复并前置“粘贴订阅链接”入口。
- iKun / Pokemon 账户卡、登录态、同步、签到和订阅导入闭环。
- 统一 Dio 错误、网页加载错误和订阅解析错误的用户提示。

### Phase 2：仓库化页面

- 将机场业务从仪表盘中的临时区块提升为独立“机场”页。
- 增加订阅仓库列表、来源标签、更新状态、流量和到期信息。
- 支持同一机场多个订阅源与手动订阅共存。

### Phase 3：运行态融合

- 总览页显示机场状态与 Mihomo 运行状态的关联。
- 订阅更新后显示节点变化摘要。
- 机场签到、刷新和节点更新使用统一的任务状态组件。

### Phase 4：可维护性

- 为每个机场 adapter 增加 HTML 结构样本和漂移测试。
- 诊断页支持导出脱敏请求日志。
- 所有敏感会话只进入系统安全存储，不写入源码、日志和截图。

## 当前版本的直接调整

- 登录页采用机场钥仓原生品牌外壳，官方网页只负责站点特有表单和验证。
- 机场总览直接提供“粘贴订阅链接”，不再要求先登录机场或先进入配置页。
- 机场账户面板同时提供自动发现订阅和手动导入订阅。
- iKun 的 `/user/subscribe_log` 只作为订阅记录来源，不能被当成订阅 URL 本身。
