# 机场钥仓产品设计

## 定位

机场钥仓不是把机场网页塞进代理客户端，也不是把三个开源项目的页面拼在一起。
它是一座本地优先的移动端“机场管理仓”：用户可以集中管理多个机场账户、订阅来源、签到状态、流量与节点运行状态；机场网页只负责完成站点特有的登录与验证，应用负责统一管理和呈现结果。

## 三个参考项目的边界

| 参考项目 | 吸收的能力 | 不直接照搬的部分 |
| --- | --- | --- |
| Yucon | 多账号看板、状态筛选、账户卡片、批量同步与签到 | AI 站点、密钥管理和它的品牌视觉 |
| SlClash | Mihomo 内核承载、订阅/配置/代理链路、Android 生命周期和高信息密度控制 | 原有页面层级不作为机场业务的最终信息架构 |
| linux-sb-mobile | 官方网页结构解析、Cookie 会话、本地状态、移动端 WebView 业务适配和结构自查 | 社区内容、论坛业务与 React Native 页面实现 |

网页适配层必须保持独立：机场页面变化时只更新 adapter，不把站点选择器、HTML 正则和登录态处理散落到 UI 中。

## 机场钥仓自己的设计语言

### 视觉关键词

“仓库感、状态感、轻量运维感”。界面要让用户一眼看到有哪些机场、哪个需要处理、订阅是否新鲜、代理是否正在运行。

### 颜色令牌

- Vault Indigo `#5B61FF`：主操作、iKun、链接和选中状态。
- Signal Teal `#2CC7C9`：Pokemon、同步成功、网络状态。
- Ink Navy `#17213F`：深色主题的背景与高层级文本。
- Paper `#F6F7FB`：浅色主题页面底色。
- 状态色只表达状态：成功、提醒、失败、过期，不用于装饰性渐变。

机场颜色只作为身份标签，不改变整套页面布局；这样用户切换机场时仍然知道按钮在哪里。

### 布局规则

- 首页首屏先呈现“总状态”，再呈现单个机场卡片。
- 账号、订阅和节点是三个独立对象：账号登录成功不等于订阅已经导入，订阅导入成功也不等于代理已经启动。
- 高频动作保持在卡片内：绑定、刷新、签到、导入、复制；危险动作放进详情页。
- 所有手动导入入口必须可见，不能只在自动解析成功后显示。
- WebView 只占业务内容区域，外层始终使用机场钥仓的标题、状态栏、错误提示和完成操作。

## 信息架构

### 1. 总览

展示全局代理运行状态、今日流量、已绑定机场数量、待处理提醒和最近同步记录。首屏提供“粘贴订阅链接”“添加机场”“启动/停止”三个入口。

### 2. 机场

每个机场是一张状态卡，包含：账户标识、流量/到期、签到状态、订阅状态、最近同步时间和待处理错误。点击进入机场详情，完成绑定、刷新、签到、订阅复制和手动导入。

### 3. 订阅

这是所有 Profile 的仓库，不依赖机场账户是否绑定。支持完整 URL、剪贴板、二维码、文件和机场自动发现；每条订阅显示来源、请求头状态、更新状态、节点数量、流量头和到期时间。

### 4. 节点

沿用 SlClash 的 Mihomo 运行语义，集中处理策略组、节点、延迟测试、代理模式和启动状态。机场业务不改写节点配置，只提供来源和状态。

### 5. 工具与设置

包含备份恢复、网页适配诊断、网络路由、资源更新、主题、隐私和关于。网页解析失败时，诊断页要显示入口、最终 URL、HTTP 状态、Cookie/Token 是否存在和解析阶段，而不是只显示“网络错误”。

## 核心业务流程

```text
添加机场账户 ──> 官方网页登录 ──> 保存本地会话 ──> 同步账户快照
                                      │
                                      ├──> 自动发现订阅 ──> 订阅仓库 ──> Mihomo 节点
                                      └──> 手动粘贴订阅 ──> 订阅仓库 ──> Mihomo 节点
```

自动发现失败不能阻断手动导入；登录失效不能删除已有订阅；订阅更新失败不能清空上一次可用节点。

## 分阶段实施

### Phase 1：核心链路

- 恢复并前置“粘贴订阅链接”入口。
- iKun / Pokemon 账户卡、登录态、同步、签到和订阅导入闭环。
- 统一 Dio 错误、网页加载错误和订阅解析错误的用户提示。

### Phase 2：仓库化页面

- 将机场业务从仪表盘中的临时区块提升为独立“机场”页。
- 增加订阅仓库列表、来源标签、更新状态、流量和到期信息。
- 支持同一机场多个订阅源与手动订阅共存。

### Phase 3：运行态融合

- 总览页显示机场状态与 Mihomo 运行状态的关联。
- 订阅更新后显示节点变化摘要。
- 机场签到、刷新和节点更新使用统一的任务状态组件。

### Phase 4：可维护性

- 为每个机场 adapter 增加 HTML 结构样本和漂移测试。
- 诊断页支持导出脱敏请求日志。
- 所有敏感会话只进入系统安全存储，不写入源码、日志和截图。

## 当前版本的直接调整

- 登录页采用机场钥仓原生品牌外壳，官方网页只负责站点特有表单和验证。
- 机场总览直接提供“粘贴订阅链接”，不再要求先登录机场或先进入配置页。
- 机场账户面板同时提供自动发现订阅和手动导入订阅。
- iKun 的 `/user/subscribe_log` 只作为订阅记录来源，不能被当成订阅 URL 本身。
